# OpenMusic изнутри

Подробности для тех, кто хочет разобраться в коде или что-то в нём поменять: как именно читается каждый источник, из каких модулей состоит приложение, как устроены текст песни, подбор и звук. Короткое описание для слушателя — в [README](../README.md).

## Источники

- **Spotify, плейлист по ссылке.** Нажмите «Указать плейлист» и вставьте ссылку на открытый плейлист. Вход в аккаунт не нужен. Без входа Spotify показывает только первые 100 треков плейлиста, а «Любимые треки» закрыты совсем: чтобы импортировать их, сложите их в обычный плейлист. Плейлистов можно добавить несколько.
- **Spotify, архив.** Полная история прослушиваний есть только в архиве. Запросите данные аккаунта в [настройках конфиденциальности](https://www.spotify.com/account/privacy/), затем в меню «Архив» выберите ZIP целиком или отдельные JSON-файлы истории, библиотеки и плейлистов. [Описание экспорта Spotify](https://support.spotify.com/us/article/understanding-your-data/)
- **SoundCloud.** Нажмите «Указать профиль» и вставьте ссылку на профиль или его имя. Приложение загрузит открытые лайки, ключи и вход не нужны. Артистом трека считается профиль, который его выложил. За один импорт приложение узнаёт имена 30 самых залайканных артистов и запоминает их, остальные показаны по адресу профиля; при повторном импорте имён становится больше. Повторный импорт заменяет прежний список лайков.

- **Deezer.** Ссылка на открытый плейлист или альбом: `https://www.deezer.com/playlist/…`, `https://www.deezer.com/album/…` (с кодом страны вроде `/us/` тоже), короткая ссылка из приложения `https://link.deezer.com/s/…`. Плейлист читается целиком; длинный — около секунды на каждые 100 треков.
- **Яндекс Музыка.** Ссылка на открытый плейлист `https://music.yandex.ru/users/…/playlists/…` или `https://music.yandex.ru/playlists/…`, либо на альбом `https://music.yandex.ru/album/…`. Подходят и адреса на `.kz`, `.by`, `.uz`, `.com`. «Мне нравится» импортируется, если в настройках Яндекс Музыки открыта медиатека.
- **Apple Music.** Ссылка на открытый плейлист `https://music.apple.com/…/playlist/…/pl.…` или альбом `https://music.apple.com/…/album/…/…`. По ссылке на одну песню альбома (с `?i=…`) добавляется только она.
- **YouTube и YouTube Music.** Любая ссылка с `list=…`: `https://www.youtube.com/playlist?list=…`, `https://music.youtube.com/playlist?list=…`, ссылка на видео из плейлиста. Нужна программа yt-dlp. Артист и название берутся из заголовка видео «Артист - Название», а у песен YouTube Music — из названия канала. Миксы, «Понравившиеся» и закрытые плейлисты без входа недоступны.
- **Плейлист M3U/M3U8.** Трек называется строкой `#EXTINF:…,Артист - Название`. Если путь ведёт к файлу на этом компьютере, трек получает ссылку `file://…`; файл без строки `#EXTINF` называется по тегам, а без тегов — по имени вида «Артист - Название».
- **Папка с музыкой.** Читаются теги `title` и `artist` всех аудиофайлов папки и вложенных папок, нужна программа ffprobe из пакета ffmpeg. Файл без тегов называется по имени «Артист - Название»; если артиста узнать неоткуда, файл пропускается, а итог говорит, сколько таких.

Треки из M3U и папки попадают в источник «Файлы», остальные — в источник с именем сервиса.

Импорт по ссылке читает открытые страницы и открытые API сервисов без ключей и входа, поэтому может перестать работать, если сервис изменит сайт. Для SoundCloud и YouTube в таком случае сначала обновите yt-dlp.

- **Другой сервис.** Загрузите CSV в UTF-8 с колонками `title`, `artist` и, при наличии ссылок на треки, `url`.

```csv
title,artist,url
All is Full of Love,Björk,
```

## Устройство

- `app.py` — запуск: окно Qt Quick из `ui/qml/Shell.qml`.
- `ui/qml/` — весь интерфейс, рисует видеокарта: `Shell.qml` (окно), `Home.qml`, `SearchPage.qml`, `LibraryPage.qml`, `NowPlaying.qml`, `PlayerBar.qml`, панели и меню. Шейдер фона `mesh.frag` после правки пересобирается: `/usr/lib/qt6/bin/qsb --glsl "100es,120,150" --hlsl 50 --msl 12 -o ui/qml/mesh.frag.qsb ui/qml/mesh.frag`. Заголовок «Мой поток» вверху главной — `ui/qml/HeroTitle.qml` (буквы по одной, курсив C059 + Inter Display Black); перелив цвета по буквам и по надписи OpenMusic рисует `ui/qml/fill.frag`, его пересобирают той же командой с `fill.frag`.
- Запуск начинается с заставки `ui/qml/Intro.qml` (около двух секунд, щелчок её пропускает). `OPENMUSIC_INTRO=0 python3 app.py` открывает окно сразу.
- `ui/shell.py` — объект `app`, с которым говорит интерфейс: медиатека, плеер, поиск, импорт, звук. `ui/home_quick.py` и `ui/now_quick.py` готовят данные главной и экрана «Сейчас играет», `ui/models.py` — списки треков и плиток (меняются на месте, без пересборки экрана), `ui/urls.py` — обложки и иконки, `ui/pictures.py` — картинки точно под размер на экране со скруглёнными углами (в QML их показывает `Art.qml`).
- `ui/playback.py` (очередь), `ui/audio_engine.py` (свой вывод звука с эффектами), `ui/covers.py` (обложки), `ui/pulse.py` (громкость для визуала).
- `jobs.py` — импорт в фоновом потоке; `library.py`, `spotify.py`, `soundcloud.py`, `web.py` — данные и сервисы.
- `deezer.py`, `yandex.py`, `apple.py`, `youtube.py` — плейлист или альбом по ссылке, у каждого `tracks(link)` → (название, треки); `local.py` — M3U и папка с музыкой; `ytdlp.py` — общий запуск yt-dlp для SoundCloud и YouTube. Qt не используют.
- `lyrics.py` — текст песни с таймингом, см. ниже. Qt не использует.
- `stream.py` — звук трека: ищет его через API SoundCloud (клиент берётся из yt-dlp) и отдаёт адрес потока; `Audio` скачивает трек целиком в папку `audio` рядом с медиатекой (до 1,5 ГБ), чтобы повторное и заранее найденное включение было мгновенным. Найденная страница запоминается в `streams.sqlite3`. Qt не использует. В интерфейсе им пользуются `ui/playback.py` (очередь, поиск заранее следующего трека) и `ui/lyrics_view.py` (экран «Сейчас играет» с текстом песни).
- `similar.py` — подбор похожих треков для джема и «Моего потока». Спрашивает сразу три сервиса: радио артиста и соседних артистов у Deezer (открытый API), микс YouTube по треку (через yt-dlp, ничего не скачивается) и станцию SoundCloud (ей верит, только если найденная загрузка набрала от 50 тысяч прослушиваний: после перезалива она отвечает чем попало, после официальной загрузки — почти одним тем же артистом). Ответы смешиваются в `blend()`: трек, названный двумя сервисами, идёт выше; ремиксы, slowed, live и прочие версии отбрасываются; одному артисту — не больше нескольких мест и не два подряд. Имена сравниваются по звучанию (`voice()`), поэтому «Max Korzh» и «Макс Корж» — один артист. Вызывать из фонового потока: `Similar(resolver).tracks(seed, count=40, skip=…, taste=…)`.
- Джем: «Начать джем» в меню трека (правая кнопка или три точки в строке) — трек играет, к нему собирается список из 40 похожих, он хранится в `user.sqlite3` (`jams`, `jam_tracks`, последние 20) и открывается в медиатеке кнопкой «Джемы»; когда список кончается, плеер сам добавляет ещё. «Мой поток» растёт из дюжины треков слушателя (лайки втрое вероятнее, послушанные не раз — вдвое), каждый приводит четыре похожих и ещё один свой трек — своего в потоке треть.
- Пропуски: «следующий» в первые 30 секунд игравшего трека записывается в `user.sqlite3` (`skips`). Артист, которого пропускали чаще, чем слушали, опускается в подборе, с четвёртого раза не попадает вовсе; песня, пропущенная дважды, больше не предлагается. Артистам из медиатеки даётся запас в два пропуска.
- `mixes.py` — миксы главной. Артисты медиатеки собираются в круги по данным Deezer (кто у кого в «похожих» и у кого эти списки пересекаются, `circles()`), каждый круг — микс из своих треков пополам с лучшими треками соседних артистов. Сборка (`build()`, около минуты запросов) идёт в фоне, результат лежит в `cache/mixes.json` неделю или до смены состава артистов; порядок треков меняется раз в день (`arrange()`).
- Выбор записи на SoundCloud (`stream.score`): из загрузок, подходящих по названию, выигрывает страница самого артиста и самая слушаемая; проигрывают версии (кавер, speed up, mashup…), лишние слова в названии и загрузки, где артист не назван. Имена и названия сравниваются по звучанию (`stream.voice`). Страницы, выбранные старым правилом (`CHOSEN_SINCE`), после запуска перевыбираются в фоне (`Resolver.renew`), скачанный звук проигравшей загрузки удаляется.
- `artwork.py` — обложки треков: у треков Spotify — точная обложка через публичный oEmbed Spotify, у остальных — iTunes Search API, затем Deezer API (всё без ключа), у играющего трека — обложка с SoundCloud. Файлы лежат в папке `covers` рядом с медиатекой. Qt не использует. Там же фото артистов: из Spotify (через страницу трека и oEmbed артиста) или с профиля SoundCloud. В интерфейсе: `ui/covers.py` (загрузка в фоне, проявление, цвет обложки) и `ui/pulse.py` (громкость играющего звука для визуала).
- Страница артиста — `ui/qml/ArtistPage.qml`, данные ей даёт `ui/artist_page.py`, а берёт их `artists.py` из открытого API Deezer (без ключа): фото, поклонники, популярные треки, релизы с их треками, похожие исполнители. Ответы лежат в `cache/artists` три дня, картинки в `cache/pictures`. Картинки качаются по нескольким постоянным соединениям: на каждое новое рукопожатие серверы Deezer тратят около секунды. Открывается щелчком по артисту на главной, в плеере, на экране «Сейчас играет» и в меню трека; назад — стрелка, кнопка «назад» мыши или Alt+←.
- Экран «Сейчас играет» рисуется видеокартой: `ui/qml/NowPlaying.qml` (Qt Quick), данные ему даёт `ui/now_quick.py`. Фон — шейдер `ui/qml/mesh.frag`; после правки его нужно пересобрать: `/usr/lib/qt6/bin/qsb --glsl "100es,120,150" --hlsl 50 --msl 12 -o ui/qml/mesh.frag.qsb ui/qml/mesh.frag`.

- `ui/island.py` и `ui/qml/Island.qml` — остров у верхнего края экрана: маленький показывает обложку и ритм, под курсором раскрывается в мини-плеер, при смене трека раскрывается сам на несколько секунд. В KDE и других Wayland-средах это слой layer-shell (нужен пакет `layer-shell-qt`, его единственная функция вызывается через ctypes), в X11 — окно без рамки. Остров живёт на рабочем столе: слой «bottom», над обоями и под окнами других приложений, так что он их не перекрывает; настройка «Поверх окон» (`islandOverWindows`) поднимает его на слой над окнами.
- `ui/settings.py` — настройки (`settings.json` рядом с медиатекой), экран `ui/qml/SettingsPage.qml`: остров, продолжение с того места (`session.json`), кэш звука, трей, заставка, спокойный фон, статистика прослушиваний, горячие клавиши.
- `scan.py` — «Весь компьютер»: ищет музыку в домашней папке и на подключённых дисках (`/run/media`, `/media`, `/mnt`), ffprobe смотрит длину, теги и каналы. Треком считается файл от 45 секунд до 30 минут, не голосовое и не запись, не из скрытых, игровых и программных папок, с артистом в тегах, в имени «Артист - Название» или в папках коллекции «Музыка/Артист/Альбом». Копии одного трека сливаются в лучшую по битрейту.
- Звук: `effects.py` — эквалайзер на 5, 10, 15 или 31 полосу (`LAYOUTS`, `refit` переносит кривую между ними) с полками баса и чёткости и срезами низа и верха — всё одним фильтром; 38 готовых пресетов по группам (`PRESETS`, `GROUPS`); авто-подстройка под играющий трек (`Tone`: средний спектр трека сравнивается с балансом, измеренным на готовых треках); предусиление, ширина стерео, баланс, перемена сторон, «для наушников» (crossfeed), ровная громкость, компрессор; эффекты: эхо, хорус, фленджер, «тёплая лента», lo-fi, «кассета плывёт», «убрать голос», семь помещений; анализатор спектра для панели. Свои пресеты хранятся в `sound.json`. Готовые сцены (24) — в `ui/sound_panel.py`: каждая сначала возвращает эффекты в `NEUTRAL`, потом ставит свои.
- `ui/tray.py` — значок в трее и закрытие в трей; `ui/mpris.py` — MPRIS через QtDBus: медиаклавиши, виджет плеера KDE, экран блокировки, KDE Connect.
- Тестовый запуск без экрана пользователя: `dbus-run-session` (своя шина, чтобы MPRIS и трей не появились в настоящей панели) и `kwin_wayland --virtual`.

- `userdata.py` — то, что слушатель делает сам: «Мне нравится», плейлисты, история прослушиваний (`user.sqlite3` рядом с медиатекой). `waveform.py` — форма звука скачанного трека для полосы прокрутки (через ffmpeg).

- `effects.py` — эквалайзер, пространство, 8D, винил и скорость (numpy); `ui/audio_engine.py` выводит обработанный звук сам, `ui/sound_panel.py` — панель «Звук». Для эффектов нужен numpy (`pacman -S python-numpy`), без него звук идёт без эффектов.

Интерфейс не знает, как устроен импорт: он вызывает функции из `jobs.py` и показывает строку, которую они вернули.

Профиль вкуса сортирует артистов по времени прослушивания. Если доступен только список треков, сортировка идёт по количеству разных треков каждого артиста. Данные из файлов хранятся в локальной базе SQLite. Удалить их можно через меню «Удалить импорт».

## Текст песни

`lyrics.py` берёт текст из [LRCLIB](https://lrclib.net) (бесплатно, без ключа) и отдаёт его с таймингом для экрана текста. Запрос идёт в сеть до нескольких секунд, поэтому вызывать его нужно из фонового потока.

```python
import lyrics

cache = lyrics.Cache(data / "lyrics.sqlite3")            # рядом с library.sqlite3
try:
    found = lyrics.lyrics(artist, title, duration_ms, cache=cache)
except lyrics.LyricsFailed as error:                      # нет сети, сбой сервиса
    message = str(error)                                  # готовая фраза для пользователя
```

- `found` — `None`, если текста у LRCLIB нет, иначе `Lyrics(synced, lines, instrumental)`.
- `lines` — список `Line(start_ms, end_ms, text, words)`, `words` — список `Word(start_ms, end_ms, text)`. Строка длится до начала следующей метки. Пустых строк в списке нет: пауза — это промежуток между `end_ms` одной строки и `start_ms` следующей.
- LRCLIB размечает строки, а не слова, поэтому слова делят время строки поровну, но не дольше секунды на слово: после строки может идти проигрыш. Отдельно стоящий знак вроде тире идёт вместе с предыдущим словом. Если в тексте есть пословные метки, берутся они.
- `synced=False` — есть только слова: у строк `start_ms` и `end_ms` равны `None`, `words` пуст. Так же отдаётся текст, размеченный под запись другой длины (расхождение больше 2 с), потому что его тайминг разошёлся бы с музыкой.
- `instrumental=True` — трек без слов, `lines` пуст.
- `duration_ms` — длина играющей записи. С ней выбирается разметка именно этой версии трека; без неё берётся первая подходящая по артисту и названию.
- Артист, которого сервис пишет латиницей (LSP, Monetochka), ищется ещё и в русском написании и по одному названию трека; совпадение артиста проверяется в любом алфавите (`same_artist`).
- Разметка от записи, которая длиннее или короче играющей не больше чем на 20 с, показывается как приблизительная (`Lyrics.approximate`). Текст совсем без разметки `lyrics.paced(lines, duration_ms)` раскладывает по длине трека, чтобы экран мог листать его вместе с музыкой.
- Ответ, включая «не найдено», запоминается в `lyrics.sqlite3`. «Не найдено» перепроверяется через неделю; `cache.forget(artist, title)` сбрасывает запись одного трека сразу.
- `lyrics.parse_lrc(text, duration_ms=None)` разбирает LRC отдельно: метки `[mm:ss.xx]`, несколько меток на строке, `[offset:…]`, пустые метки как паузы, пословные `<mm:ss.xx>`.

Тесты без сети: `python3 -m unittest discover tests` из папки проекта. Импорты проверяются на сохранённых ответах сервисов из `tests/samples`; `tests/test_ui.py` проверяет списки и картинки интерфейса без окна, `tests/test_effects.py` — звуковые эффекты на простых сигналах (тон, щелчок, шум). `tests/test_similar.py` — сравнение имён, разбор названий загрузок, смешивание списков и хранение джемов. `tests/test_choice.py` — выбор загрузки, круги артистов, пропуски.
